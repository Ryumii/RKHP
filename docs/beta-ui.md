# 公式サイト UIベータ

作成日：2026年10月28日／更新日：2026年10月31日／状態：デザイン・操作確認用。本番未公開。デモ共有先はGitHub Pages、CMS未接続。hCaptcha有効化は依頼者確認済み。受信箱は確認待ち

現在は、プロフィールにSNSを統合する案をベータに反映しています。5つのリンク内容は確定済みですが、統合レイアウトの採用は未決定です。

## 開き方

[index.html](../index.html)をChrome・Edge等のブラウザで開きます。npmのインストールやサーバーは不要です。人物写真と番組バナーはローカル画像です。ニュースの場面写真とWebフォントの読み込みには、インターネット接続が必要です。

JavaScriptの処理テストは[tests/index.html](../tests/index.html)を開くと実行できます。モダンブラウザを対象にしています。

## 輪郭に沿う漫画トーン

提供されたProfile1の人物に合わせて作ったSVGの輪郭形状を、写真の切り抜きと網点のマスクに共用しています。網点側のマスクを少し拡張・移動し、人物の外側だけにドット柄が見えるようにしています。

- SVGの `clipPath`：写真を人物の輪郭で切り抜く。
- `pattern`：繰り返す網点を作る。
- `mask` と `feMorphology`：輪郭を少し広げた領域に網点を制限する。
- 網点は常時表示し、オン・オフを切り替えるボタンは設けない。

輪郭は、今回のProfile1の表示用トリミングに合わせた手作業の形状です。写真を変えるだけで輪郭が自動追従する画像認識機能ではありません。細い後れ毛は輪郭を簡略化しています。別の写真や構図へ変更する場合は、輪郭を作り直すか、透過PNG・WebPのアルファを使う方法に変更します。

### 人物写真の解像度

確定したType Aとプロフィール欄には1360×1360 pxのJPEGを使用しています。トップは輪郭マスクで背景を除き、プロフィール欄は上半身中心の構図にしています。

人物写真の配置枠は最大680 CSS pxです。トップは人物・白い縁・網点のレイヤーを1.22倍に拡大するため、切り抜きの表示領域の最大幅は約830 CSS pxになります。プロフィールの写真幅は最大680 CSS pxです。200％程度の拡大を確認対象とし、無制限の拡大や4K表示での鮮明さを保証するものではありません。

### 確定した画面構成

Type Aを採用し、構図比較ボタン、B専用の輪郭・表示処理、漫画トーンの切替を削除しました。トップでは軽量化した表示用JPEGだけを読み込み、比較用の大きな原本は読み込みません。

ヒーローの説明文と各セクション見出しの装飾的な紹介文を取り除きました。プロフィール本文と、仮原稿や問い合わせの利用目的などの必要な案内は残しています。ニュースの件数表示は従来どおりです。

人物写真の原本は変更せず、ローカルで管理しています。「2」は提供された2枚目の写真です。ローカルのブラウザ内でトリミングとJPEG書き出しを行いました。GitHubと公開用フォルダーには表示用画像だけを含め、人物写真の原本は含めません。

### Web3Formsの設定と確認

メールアプリを開く方式は廃止しました。既存のHTML・CSS・JavaScriptを使い、ReactやJavaへの移行、npmの依存追加は行っていません。

[content.js](../content.js)の `contact` に公開用Access Key、通知の差出人名、共通の `subject` を設定しています。Access Keyはブラウザで公開するためのフォーム識別子です。受信先の実アドレス、メールパスワード、秘密のAPIキーは設定しません。

| 入力項目 | 条件 |
|---|---|
| お名前 | 必須、80文字以内 |
| 会社・媒体名 | 任意、120文字以内 |
| 返信先メールアドレス | 必須、254文字以内。Web3FormsのReply-To用の `email` として送信 |
| ご相談内容 | 必須、5,000文字以内。入力例・添付に関する補足説明は画面に表示しない |
| 利用目的・外部送信の確認 | 必須 |
| hCaptcha | HTTPSで必須。利用目的確認後に認証を読み込む。認証のない送信は行わない |

種類は選ばせず、1つのキーで共通の受付先に送ります。通知の件名は `[お問い合わせ] 岸谷蘭丸公式サイト` です。送信データに `inquiry_type` は含めず、複数の実アドレスや別部署への振り分けは行いません。

#### 実送信までに必要な操作

1. 事務所管理の[Web3Formsダッシュボード](https://app.web3forms.com/)で、対象フォームの受信先・通知設定を確認します。
2. hCaptchaは2026年10月30日に有効化したとの連絡を依頼者から受けています。公開前に対象フォームで有効かをHTTPSの実認証で確認し、認証なしの送信を許可する設定には戻しません。
3. [GitHub PagesのデモURL](https://ryumii.github.io/RKHP/)でHTTPSの確認を行います。HTTP・ローカルファイルからの送信は止めています。本番のCloudflareプロジェクトと独自ドメインは未設定です。
4. 人がhCaptchaを完了し、テストであることを明記して送信します。事務所の受信箱で本文・共通件名・返信先を確認します。返信元には窓口専用アドレスの利用を推奨します。
5. データの保管期間、閲覧権限、運営者のプライバシー説明、公開する受付・返信方針を確認します。

#### ローカルでの表示確認

`file://` とHTTPではフォームの表示・入力だけを確認できます。送信ボタンは無効で、スクリプトから送信操作を行ってもAPIへ送信しません。理由はフォーム下に表示します。

hCaptcha有効化前に使っていた認証なしのローカル接続テストは廃止しました。実際の認証・送信はHTTPS環境で確認し、偽の認証トークンは実APIへ送りません。

公開用HTTPSでは利用目的を確認する前にhCaptchaのスクリプトを読み込みません。ローカルでは認証スクリプト自体を読み込みません。

#### 成否の扱い

- 送信先は `https://api.web3forms.com/submit` に固定し、JSONでPOSTします。実アドレスを送信先のhidden項目やURLへ入れません。
- HTTP正常かつ応答の `success` が真の場合だけ、受付の表示とフォーム初期化を行います。APIの受付と、事務所のメール着信は別に確認します。
- 送信中は入力欄と送信ボタンを無効にし、操作の重複や送信中の編集消失を防ぎます。
- 失敗時は入力内容を保持します。通信・不正な応答・上限超過・20秒のタイムアウトを明示します。公開用HTTPSでは認証をやり直してから再試行し、自動再送はしません。
- タイムアウトでは既にサーバーが受け付けた可能性もあるため、重複送信に注意する案内を出します。

参考：[公式Ajax例](https://docs.web3forms.com/getting-started/examples/ajax-contact-form-using-javascript)、[hCaptcha設定](https://docs.web3forms.com/getting-started/customizations/spam-protection/hcaptcha)、[プライバシー](https://web3forms.com/privacy)、[データ処理契約](https://web3forms.com/dpa)。

## レギュラーメディアの設定

[content.js](../content.js)の `regularMedia` が表示用データです。ニュースとは別の配列・カテゴリで管理します。

| 項目 | 指定 | 表示・動作 |
|---|---|---|
| `id` | 必須 | 一意の英数字・ハイフン |
| `category` | 必須 | `terrestrial`＝地上波、`internet`＝ネット、`radio`＝ラジオ |
| `title` | 必須 | 番組・媒体名。リンクの読み上げ名に使い、画像の下には表示しない |
| `image`・`imageAlt` | 必須 | 番組画像のURLと代替テキスト。HTTPSの絶対URL、または `assets/regular-media/` 内のPNG・JPEG・WebPを指定。ローカルのファイル名は文字・数字・ハイフン・アンダースコア・半角／全角スペースに対応し、日本語・英大文字も使用可能 |
| `url` | 任意 | 認証情報を含まないHTTPSの絶対URL |

画像以外のタイトル・紹介文・放送枠・個別のカテゴリ表記は表示しません。PCでは4列、899 CSS px以下では2列に並べ、縦横比を保って画像全体を表示します。元画像が横長・正方形でもトリミングしません。外側の白い背景と内側の余白は付けず、青い背景に画像だけを表示します。マウスを重ねても背景色は追加せず、浮き上がる動きとキーボード操作時のフォーカス表示を残しています。

## 公開ファイルと制作資料の分離

[公開用ビルド](../scripts/build-site.mjs)は `dist` にサイト本体と表示用画像だけを生成します。仕様書・テスト・スキル設定・写真の原本を含めないことは[ビルドテスト](../tests/build-site.test.mjs)で確認します。ページ内の制作資料へのリンクは削除しました。制作資料はGitHubから閲覧します。

GitHub Actionsの手動実行で、この `dist` だけをPagesへ配信します。Cloudflareのビルド環境にも制作資料を渡さない場合は、Git連携ではなくDirect Uploadで同じ `dist` だけを送ります。デモ共有終了時はPagesを停止してからRepoをPrivateにします。公開中のコピーはPrivate化しても回収できません。
